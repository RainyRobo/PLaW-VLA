# Security policy

## Reporting a vulnerability

Report suspected security issues privately through GitHub's private vulnerability reporting feature when it is available. If private reporting is unavailable, contact the maintainers through the project website rather than publishing exploit details in an issue.

Include the affected revision, component, reproduction steps, expected impact, and any suggested mitigation. Do not include credentials, access tokens, private datasets, or personal information.

## Scope

Reports may cover PLaW-VLA code, checkpoint loading, the WebSocket policy protocol, dataset converters, or packaging. Issues in external models, datasets, simulators, submodules, and dependencies should also be reported to their upstream maintainers.

Model quality, benchmark performance, and inaccurate policy behavior alone are not software security vulnerabilities. Always evaluate learned policies in a controlled environment before physical deployment.
